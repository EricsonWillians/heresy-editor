# Heresy Editor 2.3.0

This release turns Heresy Editor into a review-first design environment while
expanding its safe project, campaign, resource, and Test in Game workflows.

## Smart sector authoring

* Added the nonmodal Smart Sector Designer for rectangles, detailed polygons,
  concave freeform rooms, wall extrusions, inset/rings, routed corridors,
  generated or existing-sector stairs, and tagged lifts.
* Added Open, Wall, and Smart Door connection semantics, including doors
  embedded in the extrusion pipeline as part of the same atomic edit.
* Added format-quantized preview and apply planning for Doom, Hexen, and UDMF,
  with deterministic topology, protected-special handling, issue navigation,
  and one Undo record per commit.
* Added searchable Floor, Ceiling, Wall, and Special controls; contextual Auto
  values; exact or relative sector properties; resizable diagnostics; shared
  grid snapping; and persistent repeat-mode authoring.
* Vendored the C++ clipping and offset subset of Clipper2 2.0.1 under its
  original license for offline, deterministic geometry planning.

## Architecture and shape vocabulary

* Added 31 ordered polygon profiles, ranging from basic primitives through
  crosses, gears, sawblades, foils, rosettes, and 288-vertex cathedral tracery.
* Added 16 architectural layouts and seven structural styles for pillars,
  arcades, cloisters, hypostyle halls, buttresses, naves, transepts, apses,
  rotundas, sanctuaries, and fortified keeps.
* Architecture can preserve an existing host sector or atomically create a
  walkable hall in clear void. Existing hosts lock from the first unsnapped
  press, supporting strongly concave rooms and layouts around holes.
* Invalid architecture remains visible with conflict geometry, exact
  point/line markers, and actionable size, spacing, ownership, and topology
  guidance instead of disappearing.

## Smart doors and lifts

* Added format-aware Smart Door planning and review for existing nonadjacent
  sectors, with explicit semantic presets, batch validation, deterministic
  Face/Track texture inference, and protected property preservation.
* Added loaded-texture browsing, preview tiles, unmistakable target/portal/track
  overlays, and working Face/Track Auto controls in both standalone and
  extruded-door workflows.
* Added configuration-declared lift behaviors, fresh typed tags, inferred
  stops and travel, selectable local triggers, and wall-alcove generation.

## Projects, campaigns, and resources

* Added versioned map titles, episode groups, multiple campaign entry points,
  normal/secret routes, and effective-route editing for WAD and PK3 projects.
* Added read-only reachability, cycle, and missing-target diagnostics.
* Added previewed marker-owned ZMAPINFO generation, freshness reporting, and
  stale-runtime Test in Game preflight without overwriting user declarations.
* Replaced fixed resource slots with a dynamic ordered file/folder list.
* Added recursive PK3 flat, sprite, and texture projection plus bounded,
  read-only package inventories and loaded-order collision diagnostics.
* Restored the last explicit project at startup while retaining the
  preference-controlled loose-WAD fallback.

## Test in Game, history, and recovery

* Added responsive recursive BiasedDoom/GZDoom discovery across environment,
  PATH, portable/build, home, and installation locations without imposing a
  Windows `.exe` suffix.
* Added editable, rediscoverable Test Settings with extension-neutral browsing
  and inline executable diagnostics.
* Save and Test in Game now preserve active-map Undo and Redo history and
  restore canvas focus, so a tested change can still be undone. Accidental
  Undo is recoverable through Redo, Ctrl/Cmd+Shift+Z, or Ctrl/Cmd+Y.
* Hardened project save, recovery, runtime metadata, package, resource, and map
  launch behavior with atomic failure paths and expanded regression coverage.

## Distribution

* Added a modern GitHub landing page with live build, CodeQL, BiasedDoom
  compatibility, latest-release, and license status.
* Linux x86_64/arm64, Windows x86/x86_64, and macOS Intel/Apple-silicon
  packages continue to be built and tested by the release pipeline.
* Release publication validates the version contract and every SHA-256
  checksum before uploading artifacts.
