BiasedDoom Integration

BiasedDoom is the primary target engine for Heresy Editor. It is derived from GZDoom and retains the Doom-family command-line and map-format interfaces used by the editor.

Current Workflow

  1. Open File / New Project or File / Manage Project.
  2. In New Project, select the game IWAD, package, and biaseddoom Source Port on the first page.
  3. Choose the campaign and resources, then verify the final destination summary before creating the package.
  4. Use Campaign Navigator / Map Details for optional titles, episode groups, additional campaign entry points, and normal or secret route relationships. The first slot remains an implicit entry. Its read-only diagnostics identify unreachable maps, potential cycles, and configured targets that are missing from the package.
  5. Use File / Generate Runtime MAPINFO to preview and publish those fields as a marker-owned root ZMAPINFO. Missing titles fall back visibly to map-slot names, and user-authored MAPINFO-family declarations are never overwritten.
  6. For PK3 projects, use File / PK3 Metadata for a bounded, read-only view of declarations, runtime-source entries, conventional resource groups, projected-name collisions, and loaded-source overrides.
  7. Use the port setup button or Tools / Test in Game. Heresy Editor searches for BiasedDoom or GZDoom automatically, including nested home and installation locations, and accepts extensionless Linux executables. Deep searches show a responsive progress dialog with current-location details and cancellation.
  8. Test Settings keeps the engine path editable, offers extension-neutral Browse and Auto Detect controls, and explains invalid selections inline. Cancelled or unsuccessful rediscovery keeps the current selection.
  9. When marker-owned ZMAPINFO is out of date, Test in Game can cancel, launch unchanged, or open the exact preview and update it before launch. Missing and user-authored declarations do not prompt.

A typical local development build in this workspace is ~/workspace/BiasedDoom/build/biaseddoom. Heresy Editor supplies -iwad, -file and -warp arguments when it launches the engine.

Compatibility Boundary

The biaseddoom profile derives from ZDoom and covers its map formats, things, action specials and dynamic lights. The pinned BiasedDoom release has been audited and adds no map-facing identifiers beyond that base.

Heresy Editor edits WAD and PK3 projects. PK3 flat, sprite, and texture resources are discovered recursively below their conventional namespace directories and exposed in the editor while saves preserve their original archive paths. New Project validates its complete three-page workflow before the safe package backend writes anything. Campaign graph fields remain editor metadata until Generate Runtime MAPINFO is explicitly confirmed. The generated root ZMAPINFO is marker-owned and conflict-safe. PK3 Metadata shows declarations verbatim and lists runtime sources without interpreting or rewriting them. It also reports uppercase eight-character flat, sprite, and texture name collisions and the current IWAD/resource/project resolution order without renaming entries or reordering sources. Campaign Navigator reports managed ZMAPINFO freshness, and Test in Game offers a previewed update when that managed output no longer matches current campaign metadata.
