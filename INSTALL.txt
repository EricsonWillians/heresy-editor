
INSTALLING (Linux)
==================

The recommended build entry point is the repository's build script:

  ./build.sh

It creates an optimized Release build in "build" and uses the project-pinned
FLTK and GoogleTest revisions.  Common development workflows include:

  ./build.sh --type Debug --test
  ./build.sh --clean --no-tests
  ./build.sh --system-fltk --system-gtest --test
  ./build.sh --help

The script supports parallel builds, safe cleaning, CMake generators, specific
targets, compiler selection, ccache, local installation, dry runs, and extra
CMake/CTest arguments.  It can be invoked from any working directory and never
installs system packages or invokes sudo.

On Debian and Ubuntu, the Linux dependencies used by CI can be installed with:

  sudo apt-get install build-essential clang cmake ninja-build libjpeg-dev \
      libgl-dev libglu1-mesa-dev libpng-dev libxpm-dev libz-dev python3

Other distributions need the equivalent C++ compiler, CMake 3.28+, OpenGL,
JPEG, PNG, X11/Xpm and zlib development packages.  FLTK and GoogleTest are
fetched at their project-pinned revisions unless their system options are used.

To configure and build Heresy Editor with CMake manually instead:

  cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
  cmake --build build -j

To install the resulting build system-wide, run:

  cmake --install build



CONTINUOUS-INTEGRATION ARTIFACTS
================================

Every successful push to the master branch publishes tested, versioned builds
on the corresponding GitHub Actions run.  The unified pipeline covers:

  - Linux x86_64 and arm64 portable tarballs
  - Windows x86_64 and x86 portable ZIP archives
  - macOS x86_64 and arm64 disk images

Each download includes a matching `.sha256` file.  Linux builds are tested with
both GCC and Clang; only the GCC build is published because both use the same
portable package layout.  Pull requests build and test the full platform matrix
without publishing artifacts.  A maintainer can also publish artifacts from a
manual workflow run.

Pushing a version tag such as `v2.5.0` runs the same complete matrix and then
publishes the packages as a GitHub Release.  The tag must match the project
version in CMakeLists.txt and have a matching `changelogs/<version>.md` file.
Release publication verifies every checksum before uploading the packages,
uses that changelog as the release notes, and marks the version as the latest.

The macOS CI downloads use an ad-hoc signature so their bundle integrity can be
verified, but they are not Apple-notarized.  Gatekeeper can therefore require
explicit approval before first launch.



COMPILING (macOS)
=================

Use CMake. You can download and install CMake from their website, or use a
third-party package manager such as Homebrew. Easiest to use is the graphical
interface version of CMake (CMake GUI).

Unlike on Linux, on Mac it's strongly advised to let CMake fetch FLTK from
GitHub; do not set USE_SYSTEM_FLTK to ON. This is needed because of some late
bug fixes on macOS FLTK.

The generated Xcode project or Makefile produces `heresy.app`, whose
user-facing bundle name is Heresy Editor.
If you generated a Makefile, there's no "make install" stage. Simply open the
produced app.



DISTRIBUTING (macOS)
====================

To distribute a signed app of Heresy Editor, you need to generate an Xcode
project first -- signing and notarizing the app is currently not supported from
the Makefile. You can also distribute the app generated by Makefile as-is, but
users will be warned that the app isn't signed, and prompted to move it to Trash
(unless they access the app from the right-click menu in Finder).



COMPILING (Windows)
===================

Use CMake, same as on macOS. Similarly, the FLTK project shall be downloaded and
built by CMake itself.



SETTING UP HERESY EDITOR
========================

Heresy Editor requires an IWAD file from one of the supported games, for
example "doom2.wad".  Heresy Editor will look for IWADs when it starts up,
but if it cannot find any then the 'Manage Wads' dialog will open
and you can browse for an IWAD file there, which will be remembered
for next time.

Heresy Editor searches once for all supported IWAD names, in this priority
order. Paths and Steam libraries are canonicalized and de-duplicated, and game
stores are searched only inside recognized classic DOOM-engine installations.

  1. The "iwads" directory in Heresy Editor's home directory.  In Linux
     this will be "~/.config/eureka/iwads" (or "$XDG_CONFIG_HOME/eureka/iwads").
     The legacy `eureka` path is retained for configuration compatibility.  It
     is created automatically the first time Heresy Editor is run (though there
     is no harm in creating it yourself).

  2. Directories in DOOMWADPATH, followed by DOOMWADDIR.

  3. Steam installations and every library listed in `libraryfolders.vdf`.
     Supported defaults include:

       Linux:  ~/.steam/debian-installation, ~/.steam/steam,
               ~/.local/share/Steam, Flatpak Steam and Snap Steam
       macOS:  ~/Library/Application Support/Steam
       Windows: the usual Program Files Steam locations

     Classic-game layouts such as
     `steamapps/common/Ultimate Doom/base/DOOM.WAD`, the rerelease directory,
     DOOM + DOOM II, Final Doom, DOOM 3 BFG, Heretic, Hexen and Strife are
     recognized. Additional Steam library disks are handled automatically.

  4. Usual user and system locations, including GOG/Heroic-style game
     collections, GZDoom data directories, XDG data directories,
     /usr/share/games/doom on Unix, and C:\DOOM-style directories on Windows.

  5. The current working directory.

  6. You can bypass searching and specify the IWAD directly with --iwad.



SETTING UP BIASEDDOOM
=====================

BiasedDoom is the primary engine target for Heresy Editor.  Build or install
BiasedDoom first, then open File / New Project or File / Manage Project:

  1. On New Project's first page, select the appropriate game IWAD and package.
  2. Select "biaseddoom" as the Source Port.  This profile derives from the
     shared ZDoom definitions because BiasedDoom is based on GZDoom.
  3. Choose the campaign/resources, then review the normalized destination and
     validation status before creating the package.
  4. Use File / Campaign Navigator / Map Details to add optional map titles,
     episode groups, additional campaign entry points, and normal or secret
     route relationships.  The first configured slot remains an implicit entry.
     Its diagnostics column and selected-map panel identify unreachable maps,
     potential route cycles, and configured targets that have not been created.
  5. For a BiasedDoom, GZDoom, or ZDoom profile, use File / Generate Runtime
     MAPINFO to preview and publish those entries, titles, routes, and endings
     as a marker-owned root ZMAPINFO.  Missing titles visibly use the map slot.
     Existing user-authored MAPINFO-family declarations are never overwritten.
  6. For a PK3 project, use File / PK3 Metadata to inspect MAPINFO-family and
     resource declarations, runtime-source entries, resource groups, projected
     basename collisions, and loaded-source overrides.  The inventory and its
     bounded text previews are read-only; diagnostics do not rename entries or
     reorder the IWAD, external resources, or project.
  7. Use the port setup button or Tools / Test in Game.  Heresy Editor first
     searches for BiasedDoom or GZDoom in PATH, nested home/build locations,
     and platform installation roots.  A typical local build is:

       ~/workspace/BiasedDoom/build/biaseddoom

     If automatic discovery finds nothing, select the engine manually.  Test
     Settings lets you type or paste the path, browse without an extension
     filter, or run Auto Detect again; its status explains invalid selections.
     Linux and other Unix executables do not need a `.exe` extension.  Deep
     searches show their current location and can be cancelled without freezing
     the editor or discarding the current selection.  When a generated ZMAPINFO
     is out of date, launch preflight can cancel, launch unchanged, or show the
     exact preview and update it first.

Heresy Editor supplies `-iwad`, `-file` and `-warp` arguments automatically
when testing a map.  The `biaseddoom` profile includes the inherited ZDoom map
formats and specials.  Campaign Navigator relationships remain editor metadata
until Generate Runtime MAPINFO is explicitly confirmed.
